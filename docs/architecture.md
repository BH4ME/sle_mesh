# 系统架构

## 1. 目标场景

目标不是微信群语音那种“多人同时说话”，而是更像导游机：

- 一个讲解员设备持续发话
- 多个游客设备只接收播放
- 游客端通常不发言
- 支持一键开始讲话和一键结束讲话

这类场景最适合先做成半双工广播式业务。

## 2. 推荐拓扑

```text
                +-------------------+
Mic/PTT ------> | Guide TX (WS63)   | ))))))  SLE  ))))))
                +-------------------+                 |
                                                      |
                      +-------------------+           |
                      | Listener RX #1    | <---------+
                      +-------------------+

                      +-------------------+
                      | Listener RX #2    | <---------+
                      +-------------------+

                      +-------------------+
                      | Listener RX #N    | <---------+
                      +-------------------+
```

## 3. 节点角色

### 讲解端

- 负责建组
- 负责 PTT 发话控制
- 负责采集音频
- 负责语音编码和分帧
- 负责向所有收听端发送语音包

### 收听端

- 负责入组
- 接收控制消息和语音消息
- 做抖动缓存
- 解码播放
- 上报电量/在线状态可选

## 4. 无线链路建议

### 首选：SLE

适合：

- 低时延
- 短距离
- 低功耗
- 设备数不大

建议把 `SLE` 用在：

- 设备发现
- 配对/入组
- 控制命令
- 语音小包传输

### 备选：Wi-Fi

只有在下面场景才建议考虑：

- 需要更高码率
- 需要更复杂网络接入
- 你已经接受更高功耗

但单颗 `WS63` 做自建 `AP` 时，公开资料里常见描述是最多支持 `8` 个 `STA` 接入，所以它也不天然适合大规模导游团。

## 5. 音频链路建议

## 5.1 MVP 音频参数

建议先用下面的语音参数：

- 单声道
- 8 kHz 或 16 kHz 采样
- 20 ms 一帧
- `IMA-ADPCM` 或 `G.726`

这样做的目的：

- 人声可懂度足够
- 带宽压力小
- 缓冲和丢包补偿更容易做

## 5.2 播放与采样

如果你坚持纯 `WS63`：

- 采样可以先走 `ADC`
- 播放可走 `PWM + RC 滤波 + 功放`

如果你想更像正式产品：

- 外接音频前端
- 或增加一个专门处理音频的 MCU

## 6. 软件模块划分

推荐把讲解端拆成下面几个模块：

- `audio_capture`
- `audio_encode`
- `voice_packetizer`
- `sle_link`
- `session_manager`
- `ptt_control`
- `jitter_stats`

收听端拆成：

- `sle_link`
- `session_manager`
- `voice_reorder`
- `jitter_buffer`
- `audio_decode`
- `audio_playback`
- `device_status`

## 7. 关键约束

这几个约束很重要，最好第一天就接受：

1. “导游机”和“多人实时对讲”不是同一个复杂度。
2. 真正的一对多实时语音，必须用低码率编码，不能直接发原始 PCM。
3. 第一版不要追求双向自由发言，否则链路调度会迅速复杂化。
4. 第一版不要追求超过 `8` 个终端，先把 `1 -> 2` 和 `1 -> 8` 做稳。

## 8. 推荐里程碑

### M1

- 讲解端按键发话
- 收听端收到开始/停止命令
- 不传语音，只验证组控

### M2

- `1 -> 1` 语音传输
- 可懂度达标
- 端到端时延可接受

### M3

- `1 -> 4`
- 引入丢包统计和抖动缓存

### M4

- `1 -> 8`
- 做稳定性和续航测试

### M5

- 补充配对、重连、电量、信道切换等产品化功能
