# 基于 WS63 的星闪队伍协同与离队预警系统

## 1. 项目定义

目标是做一套面向户外小队、巡检队伍、牧群管理的协同定位系统。

系统形态：

- 队长节点：`WS63 + Wi-Fi AP + WebUI + SLE`
- 队员节点：`WS63 + GNSS + SLE`
- 手机：通过 `Wi-Fi` 连接队长节点，浏览器查看地图和预警

核心能力：

- 队员持续上报位置
- 队长维护队伍成员状态
- 成员离队时触发预警
- 记录并显示最后位置
- 支持多支队伍的协议扩展

## 2. 总体架构

```text
                +-------------------------+
                | 手机浏览器              |
                | WebUI / 地图 / 告警     |
                +------------+------------+
                             |
                         Wi-Fi AP
                             |
                +------------v------------+
                | 队长节点 Leader         |
                | WS63                    |
                | - HTTP Server           |
                | - WebUI                 |
                | - SLE 管理              |
                | - 位置聚合/离队判断     |
                +--+---------+---------+--+
                   |         |         |
                  SLE       SLE       SLE
                   |         |         |
         +---------v+   +----v-----+   +---------v+
         | 队员1     |   | 队员2    |   | 队员3     |
         | WS63+GNSS |   | WS63+GNSS|   | WS63+GNSS |
         +----------+   +----------+   +----------+
```

## 3. 适用场景

- 徒步、骑行、巡检小队
- 研学、露营、景区编队活动
- 应急救援分组行动
- 牛群、羊群等分群管理

## 4. 系统角色

### 4.1 队长节点

职责：

- 开启 `Wi-Fi AP`
- 提供本地 `WebUI`
- 维护本队成员列表
- 接收队员位置包
- 判断成员是否离队
- 向全队广播预警
- 保存最后位置

### 4.2 队员节点

职责：

- 采集 `GNSS` 定位数据
- 周期上报位置和状态
- 接收队长下发配置
- 离队时本机告警

### 4.3 手机端

职责：

- 连接队长热点
- 访问本地网页
- 查看本队地图、成员、告警

## 5. 硬件方案

## 5.1 队长节点硬件

最低配置建议：

- `WS63` 开发板
- 电池或 USB 供电
- 蜂鸣器
- 按键 `2~3` 个
- 状态 LED

增强配置建议：

- `GNSS` 模块
- `OLED` 小屏
- 震动马达

推荐模块分工：

- `WS63`
  - 跑 `Wi-Fi AP`
  - 跑 `HTTP Server`
  - 跑 `SLE` 协议
  - 执行业务状态机
- 蜂鸣器
  - 离队、低电、掉线预警
- 按键
  - 开关机
  - 建队/解散
  - 静音/确认告警

## 5.2 队员节点硬件

最低配置建议：

- `WS63` 开发板
- `GNSS/北斗` 模块
- 电池
- 蜂鸣器或震动马达
- 状态 LED
- 按键 `1~2` 个

推荐 GNSS 模块类型：

- 串口输出 `NMEA` 的模块即可
- 优先选容易买到、供电简单、冷启动稳定的模块

接口建议：

- `GNSS -> WS63`：`UART`
- 蜂鸣器/LED/按键：`GPIO`
- 电量检测：`ADC`

## 5.3 可选网关增强

如果后面想做更强的平台，可以再加：

- `树莓派/香橙派`
- 或手机 App

但第一版不需要，手机浏览器访问队长节点就够了。

## 5.4 节点数量建议

第一版样机：

- `1` 个队长
- `3` 个队员

第二版扩展：

- `1` 个队长
- `5~8` 个队员

## 6. 软件架构

## 6.1 队长节点软件模块

- `wifi_ap_manager`
- `http_server`
- `webui_static`
- `sle_link_manager`
- `member_table`
- `position_manager`
- `alert_manager`
- `config_manager`
- `storage_manager`

### 模块说明

`wifi_ap_manager`

- 开启热点
- 分配 IP
- 维护手机接入状态

`http_server`

- 提供静态页面
- 提供本地 API

`sle_link_manager`

- 与队员建立连接
- 接收位置与状态包
- 下发心跳和配置

`member_table`

- 维护成员在线状态
- 保存最新位置、最后位置、最后时间

`alert_manager`

- 判断离队
- 触发蜂鸣器/页面告警

`storage_manager`

- 保存配置
- 保存最后离队事件

## 6.2 队员节点软件模块

- `gnss_reader`
- `sle_uplink`
- `device_state`
- `battery_monitor`
- `alert_receiver`
- `user_feedback`

### 模块说明

`gnss_reader`

- 从串口读取 `NMEA`
- 提取经纬度、时间、速度

`sle_uplink`

- 周期发送位置包
- 响应队长配置请求

`device_state`

- 维护 `team_id/member_id`
- 处理入队、离队、重连

`user_feedback`

- 离队时蜂鸣或震动提醒

## 7. 通信协议设计

## 7.1 总体原则

- 用 `SLE` 做队内通信
- 采用短小二进制帧
- 优先保证位置与告警消息
- 协议天然支持多队伍

## 7.2 基础帧头

```text
0      1      2      3      4      5      6      7
+------+------+------+------+------+------+------+------+
| magic       | ver  | type | team_id      | member_id   |
+------+------+------+------+------+------+------+------+
| seq         | timestamp_s                                |
+------+------+------+------+------+------+------+------+
| payload_len | flags | reserved | payload ...            |
+------+------+------+------+------+------+------+------+
```

建议字段：

- `magic`: 固定头
- `ver`: 协议版本
- `type`: 消息类型
- `team_id`: 队伍编号
- `member_id`: 节点编号
- `seq`: 包序号
- `timestamp_s`: 时间戳
- `payload_len`: 载荷长度

## 7.3 消息类型

- `0x01` `JOIN_REQ`
- `0x02` `JOIN_ACK`
- `0x03` `HEARTBEAT`
- `0x04` `POS_REPORT`
- `0x05` `STATUS_REPORT`
- `0x06` `ALERT_LEAVE`
- `0x07` `ALERT_RECOVER`
- `0x08` `CONFIG_SET`
- `0x09` `QUERY_REQ`
- `0x0A` `QUERY_RSP`

## 7.4 位置上报载荷

`POS_REPORT` 载荷建议：

- `lat`：`int32`，经纬度放大存储
- `lon`：`int32`
- `speed_cm_s`
- `heading_deg`
- `battery_percent`
- `fix_status`
- `sat_count`

## 7.5 队员状态载荷

`STATUS_REPORT` 建议带：

- 电量
- `RSSI`
- 温度可选
- 最近一次定位状态

## 7.6 离队告警载荷

`ALERT_LEAVE` 建议带：

- `lost_member_id`
- `last_lat`
- `last_lon`
- `last_report_ts`
- `reason`

`reason` 取值建议：

- `1` 距离超阈值
- `2` 心跳超时
- `3` 低电掉线

## 7.7 多队伍支持

协议里的 `team_id` 就是隔离关键。

规则：

- 队员只接受本 `team_id` 的控制
- 队长只维护本 `team_id` 的成员
- WebUI 支持按 `team_id` 展示

## 8. 离队判断逻辑

## 8.1 推荐判定方式

同时使用两条规则：

### 距离规则

- 计算队员与队长距离
- 大于阈值则进入预警态

### 心跳规则

- 连续 `N` 次未收到位置/心跳包
- 则进入失联态

## 8.2 推荐参数

人员队伍初始值：

- 上报周期：`3 s`
- 预警距离：`50 m`
- 严重离队距离：`80 m`
- 心跳超时：`10 s`

牛群管理初始值：

- 上报周期：`5~10 s`
- 预警距离：`80~150 m`
- 心跳超时：`20 s`

## 8.3 距离计算

建议用经纬度球面距离简化公式即可。

第一版可以直接在队长节点计算，不需要队员端参与。

## 9. WebUI 设计

## 9.1 页面目标

手机连接队长热点后访问：

- `http://192.168.4.1/`

页面尽量轻量，适配手机浏览器。

## 9.2 页面结构

建议做 4 个主要页面：

### 首页 `/`

- 当前队伍名称
- 在线成员数
- 告警摘要
- 快速跳转按钮

### 地图页 `/map`

- 显示所有成员点位
- 队长使用特殊图标
- 正常成员绿色
- 接近阈值黄色
- 离队红色
- 掉线灰色

### 成员页 `/members`

- 成员 ID
- 在线状态
- 最近位置时间
- 电量
- 距离队长距离

### 告警页 `/alerts`

- 离队事件列表
- 最后位置
- 发生时间
- 告警原因

## 9.3 地图模式建议

比赛第一版建议优先做：

- 离线平面图 / 简化二维地图

原因：

- 不依赖互联网
- 不依赖地图服务
- 现场最稳

增强版再做：

- 真实经纬度地图叠加

## 9.4 Web API 设计

建议先用简单 `JSON API`：

- `GET /api/summary`
- `GET /api/members`
- `GET /api/alerts`
- `GET /api/config`
- `POST /api/config`

返回示例：

```json
{
  "team_id": 1,
  "leader_id": 1,
  "online_count": 4,
  "alert_count": 1
}
```

成员列表示例：

```json
[
  {
    "member_id": 1,
    "role": "leader",
    "lat": 39.123456,
    "lon": 116.123456,
    "battery": 92,
    "status": "normal",
    "distance_to_leader": 0,
    "last_seen_s": 0
  }
]
```

## 9.5 刷新方式

第一版直接用：

- 前端每 `1 s` 轮询一次 API

不要一开始就做 WebSocket，先把系统跑稳。

## 9.6 前端技术建议

为降低 `WS63` 压力，建议：

- 原生 `HTML/CSS/JS`
- 单文件或极轻量多文件
- 不使用重框架

## 10. 最小开发路线

## 第 1 阶段：链路验证

目标：

- `1` 个队长
- `1` 个队员
- 队员向队长稳定发送假位置数据

验收：

- 队长串口能看到位置包
- 丢包率可接受

## 第 2 阶段：GNSS 接入

目标：

- 队员串口读取 `GNSS`
- 能正确解析经纬度
- 上报真实坐标

验收：

- 串口输出正确经纬度
- 队长端能收到真实位置

## 第 3 阶段：离队判断

目标：

- 队长根据距离与超时判断离队
- 记录最后位置
- 本地蜂鸣器告警

验收：

- 某个队员离开阈值后能触发告警

## 第 4 阶段：Wi-Fi AP + WebUI

目标：

- 队长节点开启热点
- 手机访问本地页面
- 显示成员列表与告警

验收：

- 手机浏览器能看到实时成员信息

## 第 5 阶段：地图视图

目标：

- 增加平面地图
- 把成员位置绘制成点
- 高亮离队成员

验收：

- 地图上能直观看到成员分布

## 第 6 阶段：三队协议扩展

目标：

- 支持 `team_id`
- 不同队伍消息隔离

验收：

- 至少协议和界面逻辑支持多队

## 11. 建议分工

如果是 `3` 人小组：

### 成员 A

- `WS63` 队长固件
- `Wi-Fi AP`
- `HTTP Server`

### 成员 B

- 队员固件
- `GNSS` 接入
- `SLE` 上报

### 成员 C

- `WebUI`
- 页面逻辑
- 地图绘制

## 12. 比赛演示流程

推荐演示顺序：

1. 手机连接队长热点。
2. 打开 WebUI，显示 4 名成员都在线。
3. 某个队员走远或模拟离队。
4. 队长节点蜂鸣，页面出现红色告警。
5. 地图显示该队员最后位置。
6. 队员回到阈值内，系统恢复正常。

## 13. 关键风险

### 风险 1

`WS63` 上 `Wi-Fi AP + HTTP + SLE` 并行资源压力不明。

建议：

- 第一周优先做共存验证

### 风险 2

真实地图依赖外网，不适合比赛现场。

建议：

- 主展示做离线平面图

### 风险 3

GNSS 在室内效果差。

建议：

- 演示时准备室外数据或模拟坐标模式
